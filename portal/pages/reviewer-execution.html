Reviewers as executable plugins

Each reviewer ships as a paired markdown spec + executable .mjs. Same business logic feeds three invocation surfaces. Closes Gap 4 and half of Gap 8.

CLI

For operators in a terminal. For agent harnesses that don't speak MCP. For cron jobs. For pre-commit hooks. The shell surface.

MCP

For agents reasoning in-session. Schema-validated, structured. Claude Code, Cursor, anything that mounts MCP. Replaces markdown-reviewer-invoked-by-Agent-tool as canonical path.

GitHub Actions

For CI. Runs on every PR. Findings post as PR-diff annotations. Blocking findings fail the check. Workflow template ships in the scaffold.

What a finding looks like

Per Lopopolo: "the lints are custom; we write the error messages to inject remediation instructions into agent context."

{
  "severity": "BLOCK",
  "location": "apps/portal/src/layouts/Layout.astro",
  "message": "AudienceSwitcher component not rendered in layout",
  "remediation": "Import { AudienceSwitcher } from '@blueprint/ui/audience-switcher'
                   at the top of Layout.astro, then render <AudienceSwitcher />
                   inside the navbar slot. The IA contract requires the switcher
                   on every page; placeholder labels are fine for routes not yet
                   authored.",
  "reference": "docs/portal-and-tier-ladder.md#pattern-a-the-ia-contract-mandatory"
}

An agent reading "BLOCK: AudienceSwitcher missing. Fix: import + render in Layout.astro navbar slot" can act on it directly. A human reading the same output gets the same actionable text. The finding is a remediation instruction, not just an error message.

The pair shape

Each reviewer at template/.claude/agents/blueprint/reviewers/ gets two files:

  • <name>.md — the canonical human description. What it checks, why, when it fires.
  • <name>.mjs — the executable lint. Default export with the standard signature. The single source of business logic for all three surfaces.

When the two drift, the methodology-gardening agent (independent item 3 in the prescription) catches the mismatch and opens a fix-up PR. Continuous payment, not painful bursts. Migration order: Pattern A + B conformance reviewers first; then research-completeness; then design-principles + prescription-evidence; then doc-quality + terminology-linter; then prototype-smoke-runner; then fact-check-loop orchestrator. ADR-0002 has the full plan.

Shipped equivalent — markdown specs only

Today's reviewers exist as nine markdown files under wip/blueprint/template/.claude/agents/blueprint/reviewers/. Each spec describes what to check, when, and how to report. A Claude Code agent reads the spec, pattern-matches against the repo, and emits findings.

The pattern works when Claude Code is the runtime. It fails for: non-Claude consumers (Cursor without Claude, Codex CLI, custom GPT-API harnesses), CI workflows (no agent session in GitHub Actions), automation (no shell access), the methodology-gardening agent (no programmatic way to verify reviewer behavior).

The L6 encoding from earlier this morning wired the two portal-pattern conformance reviewers into the gate table — they fire at Stage 3 + any portal-touching commit. But "firing" today means "an agent in a Claude Code session is supposed to read the markdown and invoke the Agent tool." That's the lock-in this wedge breaks.
