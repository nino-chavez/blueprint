Three subcommands cover the v1 surface

SubcommandWhat it doesReplaces
init Interactive scaffold flow. Wraps the L5 stamper for Pattern A; copy-stamps template/portal/ for Pattern B. Validates variant + tier against the matrix. Filesystem clone + paste-prompt ritual.
review Invokes a reviewer (or `--all`) against the current initiative. Loads the executable .mjs paired with each markdown spec. Output structured (`--json`) or human (default). Claude-Code-only agent invocation. Now runs in CI, shell scripts, anywhere.
upgrade Pulls latest methodology, runs migration if methodology_version changed, surfaces what's new per the changelog. Pasting docs/prompts/pick-up-blueprint-updates.md into a session.
mcp serve Spawns an MCP server over stdio exposing the reviewer set as tools. `claude mcp add --transport stdio blueprint 'npx @blueprint/cli mcp serve'`. The current markdown-reviewer-invoked-by-Agent-tool pattern. Still works as fallback; MCP-tool is canonical.
doctor Diagnostics. Checks SessionStart hook installed, methodology_version compatible, reviewer registry intact. Manual verification by reading the repo + running things.

Why npm distribution + semver

  • Universal. Every adjacent tool ships this way — create-next-app, Vite, Yeoman, Cookiecutter, Backstage's scaffolder. The pattern is the production-quality baseline.
  • Versioned upgrades. Consumer pins methodology_version; CLI's upgrade subcommand applies migration steps deterministically.
  • Trust model is npm. Operators already trust the npm registry; Blueprint doesn't have to build its own.
  • Parallel to ai-hive. Both tools converge on the same npm + Cloudflare-hosted-Worker shape. ADR-0001 ratifies this.

Shipped equivalent — paste-prompt + filesystem clone

Today's adoption flow: clone the repo, set BLUEPRINT_HOME or replicate the filesystem path, open Claude Code, paste the contents of docs/prompts/add-blueprint-to-project.md, confirm the pattern-match, scaffold by hand. Path-coupled, ritual-driven, no versioning.
