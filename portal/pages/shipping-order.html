What v1 defers

  • v2+Hosted methodology MCP server (blueprint-mcp.<tld>). v1 trust model is npm + filesystem.
  • v2+Third-party plugin SDK for reviewers. Forking is the v1 extension path.
  • v2+Custom-stack Pattern A variants (@blueprint/ui-svelte, @blueprint/ui-next). Wait for demand.
  • v2+Linear / Jira / Slack integrations. GitHub Actions covers the highest-leverage integration in v1.
  • v2+Anonymous opt-in CLI telemetry. Adds infra complexity; defer until consumer count exceeds 10.

What v1 places out of scope

  • outMultiplayer real-time alignment workspace — Appleton's Ace's territory.
  • outProduction-grade hosted SaaS (multi-tenant, billing, SOC2). Blueprint's value is distributable methodology, not hosted service.
  • outService catalog (Backstage's primary surface). Blueprint scaffolds initiatives, not services.
  • outCode-only scaffolders (CRA / Vite / Yeoman territory). When operators need code-only scaffold, they reach for those tools directly.

Shipped equivalent — ad-hoc commits to main

Today's methodology evolution: conventional-commit-prefixed PRs land on main; consumers pull-latest manually; no migration guidance per version because there are no versions. The L8 "methodology freeze during consumer migration" rule (added 2026-05-25) is the only procedural mitigation against parallel-evolution drift.

The pickup-updates prompt at wip/blueprint/docs/prompts/pick-up-blueprint-updates.md is the only consumer-facing migration mechanism. It's a paste-prompt; the redesigned blueprint upgrade CLI subcommand replaces it with semver-aware programmatic migration. The L8 freeze rule stays as procedural backstop.
