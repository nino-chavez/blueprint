Stack positioning

ai-hive is the alignment-layer companion

Blueprint sits in a four-layer stack between Appleton's Ace and Lopopolo's harness engineering. ai-hive occupies the layer directly above Blueprint — async blackboard alignment at initiative scope. subs-initiative proves the composition.

The four-layer stack

Appleton's Ace — multiplayer real-time alignment (general code dev) ai-hive — async blackboard alignment (initiative scope) ← companion Blueprint — methodology + scaffolding (initiative deliverables) Lopopolo's harness — repo-discipline for agent code (production codebase) Codex / Claude Code — agent runtime

Each layer addresses a different failure mode. Ace: multiple agents in parallel without shared context (general code). ai-hive: multiple agent sessions on the same initiative without shared blackboard. Blueprint: initiative deliverables drift across stages. Lopopolo's harness: agent-generated codebase entropy.

How subs-initiative composes both at Tier 2

subs-initiative is the canonical reference for Blueprint + ai-hive at full depth. Four named integration points:

1. Substrate

Multiple sessions register via hive_register_session, propose via hive_propose, react/synthesize on the blackboard, only spawn tasks once a synthesis is approved. Locks prevent file edit collisions. This is build-time only — disappears at ship.

2. Derive

tools/hive-board-derive/index.ts pulls live D1 state + GitHub issues, classifies by lifecycle bucket (Shipped-not-closed / In-flight / Awaiting-synthesis / Reference / Stale), writes deterministic markdown + JSON to docs/hive/. The derived files are checked into the repo — agent-legible per Lopopolo's pattern.

3. Portal surface

Pattern A portal's Inspect routes (gates.astro, coverage.astro, dependencies.astro) read docs/hive/_board.json + docs/audits/_state.json and render dashboards. Stakeholders open private-demo.example/inspect/ and see live-derived progress without touching the hive dashboard directly.

4. Ship-disappear

Hive worker is deprovisioned at ship. The derived markdown + JSON stay as historical record. The portal continues to surface them — "shell is throwaway; artifacts are forever" (L7 from this morning's encoding).

What changes in production-quality Blueprint

  • ai-hive is named explicitly as the load-bearing companion, not buried as opt-in hive.enabled: true. When an initiative declares multi-operator + brownfield/midstream, ai-hive becomes mandatory.
  • Same dual-protocol architecture in both tools. ai-hive adds a CLI alongside its MCP surface; Blueprint v1 distribution mirrors the shape. Single Worker pattern across both tools. ADR-0001 ratifies this.
  • The CLI vs MCP investigation at research/architecture/01-hive-cli-vs-mcp-with-optionality.md recommends a 2-3 day minimum-viable wedge for ai-hive's CLI (board export, proposal list, doctor, auth) to validate the architecture on real load before Blueprint adopts it.

What's out of scope

Blueprint does not try to become Ace. Multiplayer real-time alignment is Appleton's territory; the 2026-05-25 reconciliation that triggered this redesign was a zero-alignment failure at the methodology layer, but the response is procedural (SessionStart hook + methodology freeze) plus async-blackboard (ai-hive when multi-operator), not real-time-workspace. Operators who need Ace-shaped multiplayer alignment bring their own.

Shipped equivalent — ai-hive as opt-in capability

Current Blueprint treats ai-hive as one of seven optional capabilities behind a blueprint.yml flag. The hive-coordination-pattern doc names the litmus test ("if you're about to spin up two Claude Code sessions on the same repo in parallel, you need Hive") but the composition is documented as substrate, not as load-bearing alignment.

subs-initiative is the only Blueprint reference project that runs both at Tier 2. The other three reference projects (rally-hq, website-nc-v3, blog) skip ai-hive because they're solo. That's correct shape for those initiatives — ai-hive should not be forced on solo work — but the methodology should name the multi-operator case explicitly, which it currently does only as a footnote.
