# `docs/iterations/` — iteration ledger

The **non-objective axis** of the trust-restoration surface — what we tried, what we rejected, how the thesis evolved. Companion to [`../inputs/`](../inputs/) (objective axis) and [`../decisions/`](../decisions/) (the affirmative decisions themselves).

## Why this exists

Traditional due diligence cannot produce this artifact — no human team documents every rejected hypothesis with dates and rationale. AI-compressed development naturally produces this exhaust, and making it visible reframes the timeline from "suspicious" to "this is the only process that could produce this artifact."

The archaeology substrate's `iterations.py` ingester reads `_history.md` directly and emits `decision_logged` events for each ratified ADR plus `adr_superseded` events for each invalidated-paths entry. Queries like `/derive?question=why+did+we+reject+<approach>` return citation-bound answers.

## Files

- **`_history.md`** — the canonical ledger (auto-generated by `tools/iteration-derive/` from `docs/decisions/*.md` + `docs/invalidated-paths.md`)
- **`README.md`** — this file

## Structure of `_history.md`

Two sections matter:

### §1. Decision lineage (chronological)

One block per ratified ADR:

```markdown
### ADR-NNNN — <title> · `YYYY-MM-DD`

[`docs/decisions/NNNN-slug.md`](../decisions/NNNN-slug.md)

Synthesis: `<id-or-uuid>`

Proposals: `<uuid> (#N)`, `<uuid> (#N)`, ...

Lineage: extends ADR-NNNN | supersedes ADR-NNNN  (optional)
```

### §2. Rejected paths (invalidated-paths register)

One block per invalidated hypothesis:

```markdown
### IP-NN — <title>

Ruled out `YYYY-MM-DD` · Source: <synthesis or ADR or memory ref>

**Proposed:** <what was proposed>

**Ruled out because:** <rationale>
```

The iterations ingester parses both sections. Source IDs are `ADR-NNNN` for §1 entries and `IP-NN` for §2 entries.

## Generating `_history.md`

If you adopt `tools/iteration-derive/` (companion to this template), regenerate with:

```bash
cd tools/iteration-derive && npm install --no-audit --no-fund && npm run derive
```

The archaeology substrate's GH Action re-ingests on every push that touches `_history.md`, so the substrate stays current automatically.
