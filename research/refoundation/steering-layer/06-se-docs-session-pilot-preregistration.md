# SE Docs Front Door session pilot

## Trigger

The SE Docs Front Door initiative supplies a second kind of steering failure
from Film Room.

Film Room repeatedly reached an operator encounter with the wrong product
behavior. SE Docs Front Door began with the wrong work recipe. Its original
Claude session explicitly stamped `--variant=greenfield` before reading the
variant-selection contract even though the desired output was a decision about
a configured enterprise service. The stamp produced 230 files and 30,681 lines
before the session correctly narrowed Stage 2 to configuration rather than
software.

Later sponsor input changed the causal model. The original frame treated a
scattered corpus as a noisy given and retrieval as the primary intervention.
The new input established that the corpus itself is produced by a broken,
truncated process. Continuing the old pipeline would have encoded the
superseded frame into personas, prototype instructions, and a pilot.

The consumer session eventually corrected both problems, but only after
operator steering. The audit therefore tests whether Blueprint's root-only
recipe layer can make the two authority boundaries explicit without adding a
new stage, changing a public variant, or treating the executing model as the
control.

## Questions

1. Before scaffolding, can the evaluator select an authorized governing-frame
   disposition ahead of machine work that depends on it?
2. When new evidence contradicts the governing frame, can the evaluator stop
   downstream work at an explicit re-charter boundary?
3. After re-charter, can it select the first dependency-ready machine
   intervention while retaining the superseded frame as history?
4. Does the refounded K1 kernel already represent the transition without a new
   semantic primitive?

## Frozen packets and expected outcomes

### 1. Intake

An open decision chooses whether the initiative's governed output is research,
a configured service, or built software. Scaffold work depends on that
decision.

Expected:

- recipe `record-disposition`;
- only target `governing-frame-selected`;
- authored route `operator-inline`;
- handoff required; and
- no downstream scaffold action.

This is expected to fail before implementation. The current evaluator checks
blocked machine work before a dependency-ready decision, so it labels the same
target `implement-or-verify`.

### 2. Re-frame required

The founding frame is contradicted by the sponsor input. Its authored route
names the operator's `change-intent` authority and the canonical capture
artifact.

Expected:

- recipe `repair-or-revise`;
- only target `founding-frame-valid`;
- authored route `operator-inline`; and
- no corpus, prototype, or portal action.

### 3. Re-framed

The old frame is inactive and invalidated. The accepted current frame is
satisfied. Corpus census is open and dependency-ready; scope disposition and a
sponsor memo remain downstream.

Expected:

- recipe `implement-or-verify`;
- only target `corpus-census-bounds-reliable-subset`;
- default route `agent-autonomous`; and
- historical claim count greater than zero.

### 4. K1 transition

A second SE Docs specimen adds charter revision 2, an authorized re-charter,
invalidated revision-1 claims, a compatible receipt for the current problem
statement, and open current claims.

Expected:

- K1 validation passes;
- revision-1 retrieval claims are `invalidated`;
- the revision-2 problem-frame claim is `satisfied`; and
- census, boundary-decision, and sponsor-memo claims remain `open`.

## Adversarial preservation

- Existing steering fixtures retain their recipes.
- Existing K1 specimens and negative fixtures retain their results.
- Version-0 routing remains compatible.
- Generated output remains deterministic and contains no absolute user path.
- The evaluator still cannot issue a receipt, accept a frame, or re-charter.

## Distribution ceiling

Passing this pilot authorizes a root-only steering selection fix and a
retrospective K1 specimen. It does not authorize:

- edits to `template/`, public CLI behavior, or stamped defaults;
- a methodology wave;
- mutation or re-stamping of SE Docs Front Door;
- a claim that the prospective external steering threshold is complete; or
- a universal problem-statement stage.

The session may produce promotion candidates. Public adoption still requires
the separately defined prospective external pilot and support/rollback gates.
