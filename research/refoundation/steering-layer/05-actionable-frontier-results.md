# Actionable-frontier results

## Result

The preregistered actionable-frontier follow-up passed. The complete suite now
passes 114 assertions.

A version-1 packet with:

- completed local proof;
- a ready external sandbox authentication boundary;
- machine inspection blocked on that boundary; and
- final operator acceptance downstream

now selects exactly:

- recipe `run-bounded-encounter`;
- target `sandbox-auth`;
- one authored `operator-external` next action.

After sandbox authentication is marked satisfied, the same packet selects
exactly the sandbox inspection machine claim under `implement-or-verify`.

## Compatibility

All version-0 fixtures retain their prior recipes. Deterministic output,
absolute-user-path rejection, source-line diagnostics, touch-budget behavior,
and the evaluator's non-mutation ceiling remain green.

## Interpretation

An explicit execution route is necessary but not sufficient. If the evaluator
mixes a current handoff with work that cannot start until that handoff returns,
the result still fails as an operational interface.

The selected recipe must represent the current actionable dependency frontier,
not every unresolved downstream claim.

## Disposition

Continue the prospective consumer pilot with the root-only evaluator. Do not
promote into `template/`, the public CLI, or a methodology wave until the
external sandbox route is encountered and resumed prospectively.
